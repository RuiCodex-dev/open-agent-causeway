Read .cursor/rules (especially 30-ui.mdc) and docs/STYLE_GUIDE.md first. Build the Causeway web UI in a NEW folder `ui/`
(Vite + React 18 + TypeScript). Do NOT run shell commands (no npm install, no builds); only create files. A reviewer installs and builds.

Product: Causeway answers a small-business owner's "why did <metric> change?" question. It runs rival hypotheses as SQL
on Zetaris, a Skeptic challenges supported verdicts, a Verifier re-executes queries and strikes ungrounded numbers, and
Meterless H-MEM remembers facts the owner confirmed. The UI must make that process visible and every claim one click from
its evidence. All businesses are SYNTHETIC demo businesses and must be labelled "synthetic" wherever shown.

API (base URL from `import.meta.env.VITE_API_URL`, default `http://localhost:8000`):
- GET /health -> { status, model_provider, zetaris_configured, snapshot_available }
- GET /businesses -> { data_mode, businesses: [{ business_id, name, city, nace, sector, synthetic }] }
- POST /runs body { input: { question, business_id, period?, baseline? }, options: { reasoner?: "auto"|"offline", sample_mode?: boolean|null } }
  -> 202 { run_id, events, result }
- GET /runs/:id/events (Server-Sent Events). `event: trace` data = one trace line { ts, run_id, step, agent, action, ... }.
  Useful lines: agent "Hypothesiser" action "proposed" (hypotheses [{id,cause_type,proposed_by}]); agent "Analyst" action
  "query_zetaris"|"query_snapshot" (evidence_id, purpose, row_count); agent "Analyst" action "verdict" (hypothesis_id, cause_type,
  verdict, rule, confidence, role); agent "Skeptic" action "challenge" (challenges [{id,target_hypothesis_id,confounder,argument}])
  and "challenge_resolved"; agent "Verifier" action "verified"; agent "ModelRouter" action "call" (provider, model, ok).
  Finally `event: result` data = the full result object (same shape as POST /run).
- The full result shape is in `docs/api/sample-run.json` (a real run). Read it. Key fields: status ("success" |
  "needs_clarification" | "error"), data_mode, reasoner, frame, output { verdict, chain[], claims[{id,text,evidence_ids,verified}],
  struck_claims[{...,struck_reason}], rejected[{hypothesis,why,evidence_ids}], offsets[...], limitations[], what_would_change[],
  actions[], memory_used[{fact,memory_id}] }, hypotheses[{id,title,cause_type,proposed_by,verdict,confidence,role,rule,numbers,evidence_ids}],
  challenges[], verdict_changes[], evidence[{id,purpose,engine,sql,columns,rows_preview,row_count,sha256,source_tables,executed_at}],
  verification { requery[], struck, revisions }, model_calls[{provider,model,ok,failover}], execution_time_seconds.
  For needs_clarification: output.clarifying_question.
- GET /memory/:business_id -> { facts: [{ id, text, cause_type, params, created }], ledger: {...counts} }
- POST /memory { business_id, fact } -> { status, fact }

Build these components (one screen, three columns on wide screens, stacked on narrow):
1. Header: "Causeway" wordmark (Source Serif 4), tagline "The agent that argues with itself before it tells you why",
   and a MODE BADGE that always shows data mode (Zetaris live / Zetaris snapshot) and reasoner (Nemotron via <provider> /
   offline reasoner) from the latest run or /health.
2. Ask panel (left): business picker (name, city, sector, a "synthetic" tag), question textarea (Enter submits, Shift+Enter
   newline), optional period/baseline inputs, a reasoner switch (Nemotron / offline), Run button, example question chips:
   "Why did our gross margin fall in the first half of 2025?", "Why are things bad lately?".
   Memory panel under it: facts from GET /memory for the selected business, an "Add a fact the owner confirmed" input
   (POST /memory), and after a run the "used in this run" facts highlighted.
3. Live board (centre): one row per hypothesis created from trace events; status pill pending -> tested -> supported /
   contradicted / inconclusive (colours from the style guide; inconclusive = muted + dotted rule); a "proposed by" tag
   (Hypothesiser / Skeptic / Memory); Skeptic challenges shown as threaded replies under the targeted row with their
   outcome; a small running count of Zetaris queries; a collapsible raw trace list.
4. Explanation card (right, appears with the result): one-sentence verdict (Source Serif 4, large), causal chain, claims
   with evidence chips (click or press E on a focused claim to open the drawer), STRUCK claims rendered with a single ink
   strike-through line plus the Verifier's reason, offsets, rejected rivals with why, limitations, "what would change this",
   actions. Footer: re-executed queries count, struck count, execution time, model calls by provider.
5. Evidence drawer (slide-over): purpose, engine badge ("Zetaris Lightning" or "Zetaris snapshot / DuckDB"), the exact SQL
   in IBM Plex Mono (wrap, copy button), first rows as a table, row count, sha256 (short + full on hover), source tables,
   executed_at. Esc closes; focus is trapped while open.
6. Clarification state: show the clarifying question in the card area and focus the question box.
7. Error state: show error type/message without crashing.
