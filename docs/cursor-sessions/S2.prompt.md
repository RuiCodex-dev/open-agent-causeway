Official instruction from meterless.ai/engines.html (POWER, 'Add Meterless as a provider'), quoted verbatim:
"""
The contract (Meterless Runtime 1.4, provider contract v4):
- Provider id meterless, name Meterless Runtime, default base URL http://127.0.0.1:8088/v1. Accept a pasted URL with or without a scheme, /v1, /v1/chat/completions, /v1/models or /healthz, and normalise it to <host>/v1. Never produce /v1/v1.
- Auth is real. Send Authorization: Bearer <token> on every call. The runtime writes the token to <stateDir>/proxy-token. Store it under the key meterless_runtime_token. The placeholder rt-local is rejected.
- Send meterless-app: <a stable lowercase id for this app> on every request, and meterless-scope: user on chat.
- Model ids are routing modes, not models: meterless/<disposition> (auto, fast, deep, cheap, local, fusion), meterless/<class> and meterless/<class>.<disposition>. Read them from GET /v1/models and keep any meterless/* id you don't recognise.
- GET /healthz only proves the process is up. GET /v1/models decides: 401 or 403 is "unauthorized" (show a field to paste the token), 200 with meterless ids is "online", anything else is "offline".
- Auto Detect tries ports 8088, 8090, 8787 and 11434 on 127.0.0.1, localhost and [::1], and saves the first online or unauthorized hit.
- Plain text requests stay a string, exactly like OpenAI. Use a 180 s timeout, because a model load can take minutes.
- If the user pastes a connect link (http://<host>:<port>/connect#k=<key>), take the base URL from its origin + /v1 and the key from k. Never log it.
You are done when a wrong token shows unauthorized (not offline), Auto Detect finds the runtime, and a plain text request on meterless/auto returns a string.
"""

How to apply it in THIS codebase:
1. Implement src/models/providers/meterless.ts exporting class MeterlessProvider implements ChatProvider (see src/models/types.ts; id "meterless").
   - constructor(opts: { baseUrl?: string; token?: string; appId?: string; model?: string; fetchImpl?: typeof fetch; timeoutMs?: number }).
   - chat(req): POST {base}/chat/completions with model = opts.model (default meterless/auto; role "fast" may use meterless/fast), messages, max_tokens, temperature, stream:false;
     headers Authorization: Bearer <token>, meterless-app: <appId>, meterless-scope: user, content-type json. Timeout 180 s (AbortSignal.any with req.signal).
     Return ChatResult (provider "meterless", model = the model actually reported in the response or the requested mode, latency_ms, retries 0).
     Throw ProviderError(status 401/403 => retryable false, 429/5xx/timeouts => retryable true).
   - status(): Promise<"online"|"unauthorized"|"offline"> via GET {base}/models per the contract; listModels(): string[] of meterless/* ids.
   - Exported pure helpers: normaliseBaseUrl(input) per the contract (never /v1/v1), parseConnectLink(text) returning {baseUrl, apiKey, model, app, healthUrl} or null,
     and autoDetect(fetchImpl, token?) trying ports 8088, 8090, 8787, 11434 on 127.0.0.1, localhost and [::1], returning the first online or unauthorized base URL.
   - The placeholder token rt-local must be rejected (treated as missing). Never log the token or a connect-link key.
2. src/models/providers/meterless.test.ts: vitest tests with a fake fetch covering: URL normalisation cases (with/without scheme, /v1, /v1/chat/completions, /v1/models, /healthz), connect-link parsing (valid, trailing slash, invalid path, missing k),
   status online/unauthorized/offline, a chat call sending the three headers and returning the string content, rt-local rejected, auto-detect picking the first online/unauthorized port.
Keep it dependency-free (global fetch), strict TypeScript, ESM imports with .ts extensions like the rest of src.
